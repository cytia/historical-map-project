# 数据分片与关系层模型

本项目把稳定实体、物理地点和覆盖关系分开维护。目录分片只服务于校勘和协作，不改变历史实体的稳定 ID。

## 稳定实体

- `Place` 表示具有稳定空间身份的物理地点。行政单位、卫所或土司机构可以通过 `seatPlaceId` 共用同一个地点。
- 行政单位保留现有的 `administrativeUnits` 记录。
- 都司、卫所、千户所和土司机构使用独立的军事或特殊治理分片；在具体史料关系完成前，不把它们强行改写为普通府州县。

## 关系与覆盖

以下内容不能写入单一 `parentId`：

- 五军都督府、都司、行都司、留守司与卫所之间的军事隶属或编制关系。
- 总督区、巡抚区、分守道和分巡道等管辖关系。
- 明、清、顺及其他武装力量在战争期间的实际控制、占领、声称或争议关系。

这些内容分别进入关系层，并保留关系自身的有效时间、来源、可信度和校勘说明。一个地点或单位可以同时拥有多条不同制度体系的关系。

## 当前分片约定

- 行政单位按行政区域分片。
- 当前可由名称确认的卫所和千户所进入 `units/military/`。
- 当前的宣慰、宣抚、安抚、招讨、长官和土巡检等记录进入 `units/special-governance/`，这只是维护分片，不替代逐项历史分类。
- `places/` 独立于单位类别分片，避免共址地点被复制。
- `relations/` 与 `geometries/` 先建立目录和准入规则，待具体史料和字段确定后再接入正式数据汇总。

## 不能混用的语义

- 机构的正式隶属不等于其驻地所在行政区。
- 机构的制度归属不等于战争期间的实际控制者。
- 点位位置不等于该机构的辖区边界。
- 组织层级不等于地图上的面状区域。

## 视图模式与颜色语义

行政、管辖和势力是三套独立的空间语义，不合并为一个单位字段，也不要求始终同时着色。地图使用一个主视图模式决定当前点位的归属色，同时允许未来把其他体系作为低透明度的辅助覆盖层叠加：

1. **行政视图**：按当前时间切片中的一级行政区域归属着色。
2. **管辖视图**：按巡抚、总督等管辖关系着色；关系未录入时不显示伪造归属，使用中性色。
3. **势力视图**：按特定时间内的实际控制者、占领者或争议声称者着色；不能用行政单位的 `polityId` 代替战争控制关系。

渲染约定如下：

- 点位实体不保存固定 `color`；颜色由当前视图模式和关系字段动态计算。
- 机构类别使用形状、边框或标记层区分，不用归属色同时承担类别语义。
- 可信度使用透明度、虚线或说明文字表达，不再增加一套容易混淆的颜色。
- 选中和悬停使用光晕与亮度变化，覆盖归属色但不修改数据归属。
- 地貌是基础层；未来面状控制区、管辖区和行政边界分别使用独立 source/layer 组，再按主视图顺序叠加。

当前前端保留行政视图，并为军事图层提供独立的军事着色接口。行政着色下，军事点位按所在省级地区使用行政 token；行都司和留守司可使用同一省级基础色的军事变体。军事着色按五军都督府归属计算，只作用于军事点位和军事关系线，不改变行政点位的行政色。管辖与势力视图仍暂不启用，直到对应关系具备有效时间、来源和可信度记录。

## 通用层级与选择接口

地图界面使用一套跨制度体系的层级范围：

- `overview`（总览）：行政显示府、直隶州等一级单位；军事显示都司类与卫等一级显示单位，不展开“所”；
- `unit`（本级）：行政选中一级单位后显示其二、三级单位；军事选中都司类或卫后，分别展开所属卫或“所”；
- `domain`（全域）：行政选中一级单位后显示本省全部二、三级单位；军事选中一级单位后显示所属区域内全部一级、二级军事单位。

行政、军事和特殊治理单位各自解释这三个状态，但不共用 `parentId` 或选择链。军事显示层级由 `militaryKind` 判定，卫指向都司的线段属于军事隶属关系，不改变卫的总览级别。行政点击进入府州县关系，军事点击进入五军都督府—都司—卫所关系，未来宣慰司等特殊治理单位进入自身关系链。共址只提供跨体系跳转，不能把军事或特殊治理单位写入行政下辖列表。
