# 应天府行政边界绘制试验方案

本文定义公元 1600 年应天府行政边界试验的启动条件、研究方法、数据要求和验收标准。试验在都司卫所点位图层完成并验收后启动；在此之前，项目不展示合成行政面或占位边界。

## 目标

- 验证能否依据可引用史料和许可兼容的空间资料，独立重建一条可审计的府级历史边界。
- 建立边界段证据、争议方案、几何校验和发布资格的完整流程。
- 验证行政疆界叠加于山川地貌之上的悬停、点击、选中与详情联动。
- 为后续南京直隶府州边界提供是否继续投入的判断依据。

试验结果只能称为“历史边界重建”。除非存在对应年代的可靠测绘依据，不使用“精确边界”或“真实测量边界”等表述。

## 不在试验范围内

- 不同时制作南京直隶十四府、四直隶州的完整边界。
- 不从治所点生成 Voronoi、凸包、缓冲区或其他替代行政面。
- 不把现代行政区边界直接改名为明代边界。
- 不描摹 CHGIS 或其他禁止再分发、禁止商业使用的多边形。
- 不以视觉连续或游戏交互需要填补无法解释的边界线。

## 启动条件

开始采集边界证据前，必须同时满足：

1. 都司卫所点位图层完成，并通过结构、时间、来源和地图交互验收。
2. 应天府及相邻府州的 1600 年行政名录、父链和治所位置已经稳定。
3. 已确认至少一种允许商业使用、允许必要衍生和再分发的空间参考来源。
4. 已取得 CHGIS 书面授权，或确认试验完全不依赖其受限几何。
5. 已确定史料影像、转录文本和研究成果的引用与使用权限。
6. 已复核公开展示历史疆界所需的地图审核与内容表示要求。

任一条件不满足时，保持现有山川地貌、治所点和隶属关系表达，不启动行政面制作。

## 研究范围

- 时间切片：公元 1600 年，允许史料以覆盖该年的有效区间记录。
- 目标单位：应天府。
- 必须同步核对：应天府所属八县及所有相邻府、州、县。
- 几何坐标：发布 GeoJSON 使用 WGS 84，经度在前。
- 研究粒度：以边界段为基本单位，闭合多边形是证据汇总产物。

## 证据来源

历史依据优先次序：

1. 覆盖万历时期的应天府志、所属县志和相邻府县地方志。
2. 《明史·地理一》、会典及同期行政文书。
3. 年代和辖属关系可确认的明代区域地图。
4. 经过校勘的历史地理专著、论文和学术 GIS，仅在许可允许时使用其空间成果。

空间依据优先使用许可兼容的河流、湖泊、山脊、海岸、地形和公开行政参考数据。现代行政线只能作为定位线索；若没有历史连续性证据，不得成为边界结论。

## 边界段证据表

每一段候选边界至少记录：

| 字段 | 内容 |
|---|---|
| `id` | 不含时代语义的稳定标识 |
| `leftUnitId` / `rightUnitId` | 边界两侧的行政单位 |
| `validFrom` / `validTo` | 适用时间及精度 |
| `evidenceText` | 四至、接壤或界址原文 |
| `sourceId` | 来源记录及卷页 |
| `spatialReferenceId` | 用于现代定位的许可兼容空间来源 |
| `method` | 文献界址匹配、自然地物跟随或相邻关系推定 |
| `boundaryAccuracy` | `documented`、`reconstructed` 或 `disputed` |
| `confidence` | `high`、`medium` 或 `low` |
| `alternatives` | 争议方案及其证据 |
| `reviewedOn` | 最后校勘日期 |
| `publicationEligibility` | 公共、商业、非商业或内部使用资格 |

## 制作方法

1. 列出应天府八县与全部相邻单位，形成无遗漏的邻接矩阵。
2. 逐府、逐县摘录四至、接壤、河山界址、迁治和析置记录，不先画线。
3. 将能够定位的界址匹配到许可兼容的自然地理参考层，并记录匹配理由。
4. 在可重复的 GIS 编辑或代码化处理流程中按边界段分别绘制；QGIS 可以作为人工校勘工具，但不是项目启动前提。争议方案并存，不在编辑阶段强制合并。
5. 对缺少直接界址的区段，仅在两侧辖属、相邻关系和空间依据能够共同约束时标记为 `reconstructed`。
6. 检查共享边、闭合、非法自交、碎片、异常重叠和坐标参考系。
7. 由第二人或第二来源复核后，才将合格边界段组合为应天府候选多边形。
8. 生成发布数据时保留边界段与来源关系，不直接编辑生成后的 GeoJSON。

## 地图表达

- 山川地貌持续显示在行政疆界下方。
- `documented` 使用清晰实线；`reconstructed` 使用较弱线型；`disputed` 展示多方案或争议说明。
- 填充保持半透明，不遮蔽河流、山脉和地形晕渲。
- 点击行政面选择应天府；治所点和标签保持更高命中优先级。
- 详情中展示目标年份、重建方法、可信度、主要来源和争议说明。

## 准入标准

候选多边形进入正式时间切片前必须满足：

- 所有边界段均有历史依据、空间依据、方法和发布资格记录。
- 不存在依靠自由直线或点位算法闭合的区段。
- 与所属县和相邻府州的行政关系没有无法解释的冲突。
- 共享边使用同一几何，不存在裂缝、重复描绘或异常重叠。
- 边界精度与界面线型一致，用户不会将重建线误读为实测线。
- 数据允许进入计划中的免费版本和商业发布场景。
- 几何、时间、来源、许可和敏感信息校验全部通过。
- 公开展示前已完成适用的地图审核与合规复核。

## 停止条件

出现以下任一情况时停止行政面制作，只保留研究记录：

- 无法取得商业兼容的空间参考数据。
- 关键区段只能从现代行政边界反推，缺少历史连续性证据。
- 为闭合多边形必须大量使用任意线段、Voronoi、凸包或插值。
- 相邻单位的史料关系存在重大矛盾且无法保留为可解释的争议方案。
- 来源许可不允许衍生、再分发或预定商业使用。
- 试验成果无法通过地图审核或发布合规要求。

停止试验不影响行政治所点、行政父链、山川地貌和都司卫所点位图层继续开发。

## 预期产物

- 应天府及相邻单位的边界证据目录。
- 边界段证据表与争议方案记录。
- 许可与发布资格清单。
- 可重复的 GIS 工程或代码化几何处理说明；若使用 QGIS，保留工程和导出参数。
- 通过准入标准时生成的候选 GeoJSON；未通过时提交停止报告，不生成行政面。
- 按[行政疆界显示与交互规范](administrative-boundary-display.md)完成地图交互、视觉层级和移动端行为的验证记录。
