# 军事图层与通用层级显示约定

本文记录都司、行都司、留守司、卫所及五军都督府接入现有地图 UI 的显示和交互决定。本文只规定显示接口和关系语义，不替代军事名录、坐标和关系的历史校勘流程。

## 图层

标题栏图层入口新增“都司”。该开关统一控制：

- 都司、行都司和留守司；
- 卫、千户所及其他已准入的军事点位；
- 军事关系线、流光段和军事标签。

军事点位与府州治所不使用同一地图点位图层。府州治所使用圆点，军事机构使用正三角形。机构类型不再通过额外图层开关区分。

## 着色

着色入口保留“行政”，新增“军事”。两者作用域不同：

- 行政：行政单位按一级行政区域着色；军事点位复用所在省份 token。行都司和留守司使用同一省级基础色的军事变体；没有明确行政所在关系时使用中性色；
- 军事：只改变军事点位和军事关系线，按五军都督府归属使用五组军事 token；行政圆点、行政下钻点和其他非军事单位不改变颜色。

军事点位不保存固定颜色。行政或军事颜色都由地图要素属性和当前模式动态计算。正三角形负责表达机构类别，颜色负责表达归属体系，选中状态继续使用光晕和亮度变化。

## 军事显示层级

军事制度隶属和地图显示层级分开处理。都司、行都司、留守司与卫都属于地图一级显示单位；卫可以通过军事关系线指向都司，但不会因存在军事隶属而在总览中降为下级。千户所、守御千户所等“所”属于地图二级显示单位，只在选中所属卫后展开。

当前贵州试点中，8 个卫是一级显示单位，5 个千户所是二级显示单位；都司、行都司和留守司尚未进入该试点名录。`militaryKind` 是显示层级判定依据，行政 `parentId` 不能替代军事隶属关系。

## 通用层级

原“行政层级”入口改名为“层级”，选项统一为：

| 状态 | 显示含义 |
| --- | --- |
| 总览 | 无论是否选中，都显示全部军事一级显示单位，不显示“所” |
| 本级 | 选中一级军事单位后展开对应下级；都司类单位展开所属卫，卫展开所属“所” |
| 全域 | 选中一级军事单位后，显示当前所属区域内全部一级、二级军事单位 |

行政、军事以及未来宣慰司等特殊治理体系共用状态名称和操作逻辑，但各自解析自己的关系数据：

- 行政总览／本级／全域对应府州县点位和行政关系；
- 军事总览显示都司类与卫，本级按选中的一级单位展开所属卫或“所”，全域显示当前所属区域内全部军事一级、二级单位；
- 特殊治理体系按自身正式隶属链解释同一组状态。

“本级”和“全域”的空间过滤必须使用明确的所在或共址关系；军事隶属不能由军事点位与府州县的空间接近推断。

## 选择链

行政单位和军事单位保持相互独立的选择域：

- 点击州府、州、县进入行政详情和行政关系链；
- 点击都司、行都司、留守司或卫所进入军事详情和军事关系链；
- 共址点使用统一命中接口，但选中后进入对应体系；
- 跨体系链接只用于返回同址行政单位或军事单位，不合并详情、不改写父链。

前端状态使用通用层级范围，并分别保存行政选中 ID 和军事选中 ID。军事隶属、五军归属、行政所在和共址关系在数据接口上保持独立字段，军事关系不写入行政 `parentId`。

## 关系线

军事关系线复用行政流光线段的几何和动画实现，但使用独立的军事关系 source、layer ID 和颜色 token。行政关系数据仍只表达府州治所到区域治所的行政关系，军事关系不得混入该数据源。

## 数据准入

军事单位进入军事域后，组装器保留 manifest 中的 `domain`，前端据此排除特殊治理分片。军事点位必须声明 `militaryKind` 以确定地图显示层级；`fiveArmyId` 只表达五军都督府归属，不替代军事隶属。历史隶属关系仍须进入关系层并带有有效时间、来源、可信度和审计信息。
