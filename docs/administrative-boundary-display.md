# 行政疆界显示与交互规范

本文定义省级与府级行政疆界在主地图中的显示方式、交互行为和实现边界。它只规定地图表达，不替代[历史边界重建规范](boundary-reconstruction.md)和具体区域的证据校勘方案。

## 目标与范围

- 行政疆界是叠加在山川地貌上的主地图图层，不替换或遮蔽自然地理底图。
- 正式面状数据只制作省级和府级；不因地图下钻而自动生成县级边界。
- 府级面与府州治所点使用同一套行政选择接口，点击结果进入同一个详情面板。
- 视觉参考采用大战略地图的区域浏览、层级缩放和相邻区域切换逻辑，不复制具体游戏素材、图标或界面。
- 所有正式历史几何必须经过来源、时间、许可、拓扑和发布资格审查；内部合成几何不得进入正式图层。

## 地图职责与数据边界

行政边界几何作为静态 JSON/GeoJSON 资源维护，业务状态由 Zustand 保存，MapLibre 只负责源、图层、相机和地图事件。地图模块不得拥有历史证据或来源判断。

边界段证据与闭合后的府级面分开保存。府级面是证据汇总产物，不能替代边界段与来源关系。发布数据中的几何记录至少提供：

- `unitId`、`level`、`regionId`；
- `validFrom`、`validTo`；
- `boundaryAccuracy`、`confidence`；
- `method`、`sources`、`publicationEligibility`；
- 坐标参考系和最后校勘日期。

发布 GeoJSON 统一使用 WGS 84，经度在前。MapLibre 图层只读取已经组装并校验的数据，不在浏览器端推算边界。

## 图层顺序

从下到上保持以下顺序：

1. 地形晕渲、地貌和现代自然地理参考层；
2. 历史河流、湖泊等物理地理层；
3. 省级行政面填充与省界；
4. 府级行政面填充与府界；
5. 可信度弱化线和争议方案线；
6. 行政面悬停、选中和相邻区域反馈；
7. 府州治所点、县治点、军事点和标签。

治所点、军事点和标签必须保持高于行政面命中层的渲染和点击优先级。行政面不得使用不透明实色覆盖山脉、河流或湖泊。

## 缩放层级

缩放阈值以视觉验收为准，以下为首版初始目标：

- 总览缩放：显示省级面和省界，隐藏大部分府级标签；
- 区域缩放：逐步显示府级面、府界和府级治所；
- 府级下钻：保持府级面，显示选中府下辖县治点和资料入口，但不显示县级面；
- 高缩放：继续保留府级选中状态，允许查看治所与地貌细节，不改变历史行政层级。

省级和府级图层的可见性由缩放和图层开关共同决定。不得通过“高缩放自动显示县界”改变本项目只制作省级和府级边界的范围。

## 视觉表达

使用现有主题中的行政色系、纸张色、地貌色和朱砂强调色，保持低饱和、半透明和地形优先：

- 普通行政面使用低透明度填充，确保底层河流和山脊可辨；
- `documented` 使用清晰实线；
- `reconstructed` 使用较弱线宽或虚线；
- `disputed` 使用更弱的虚线、差异化说明或可切换方案，不伪装成确定边界；
- 悬停只提高局部填充和边线对比度，不让整张地图闪烁；
- 选中区域使用朱砂色边线、轻微光晕和适度填充增强；
- 非选中区域只降低对比度，不完全隐藏相邻单位；
- 图例必须同时说明行政等级、边界可信度和研究状态。

视觉效果应让用户感知“这是历史重建的行政空间”，不能误读为现代测绘线或实测面积。

## 交互行为

### 图层开关

图层栏保留“边界”开关。没有正式合格的历史几何时，开关保持禁用，并明确说明原因；不得为了验证点击流程而静默加载合成面。

### 悬停

悬停行政面时：

- 高亮当前面及其边界；
- 显示单位名称、行政等级和边界可信度；
- 不改变全局选择状态；
- 移出后恢复原有视觉状态。

### 点击

点击府级面等价于点击该府的治所点：

1. 将行政单位 ID 写入现有可序列化选择状态；
2. 打开或更新行政详情面板；
3. 显示行政路径、下辖单位、治所定位、边界重建方法、可信度和来源；
4. 保留地图上的选中边线和相邻区域上下文。

点击行政面不得直接修改历史数据，也不得把 MapLibre 实例或 DOM 节点写入 Zustand。行政面事件卸载时必须移除，避免重复注册。

### 点位优先级

当治所点、军事点或标签与行政面重叠时，点位优先响应点击。用户仍可通过详情面板或行政列表进入对应行政单位，避免大面层阻断精确目标选择。

### 移动端

移动端保持与点位选择相同的结果：地图上完成选中，详情面板以现有的移动端布局展开。悬停专属信息不得成为移动端唯一的信息入口，可信度和来源必须在点击后的详情中可见。

## 实现约束

- 行政面使用独立的 MapLibre source/layer 组，不复用治所点 source。
- 面填充、边界线、悬停状态和选中状态职责分离，避免通过改写原始几何实现交互。
- 颜色由当前行政显示模式和区域 ID 计算，几何数据不保存固定 UI 颜色。
- 可信度和研究状态由 feature 属性驱动线型、透明度和说明，不依靠用户记忆图例。
- 行政面选择复用现有单位选择与详情联动接口，不另建一套行政选择树。
- 正式构建只读取已通过校验的边界资源；内部测试夹具必须在目录、清单和构建流程上隔离。
- 省级与府级边界共享边必须来自同一份已校勘几何，不能在前端分别绘制两条近似线。

## 应天府试验验收

应天府试验至少验证：

- 边界开关能正确显示和隐藏正式府级面；
- 地形、河流和湖泊在行政面下仍可辨识；
- 缩放时只出现省级和府级边界，不出现县级面；
- 点击应天府面与点击应天府治所进入同一详情状态；
- 治所点和军事点在重叠处保持点击优先级；
- 悬停、选中、取消选中和相邻府切换状态稳定；
- `documented`、`reconstructed`、`disputed` 的视觉差异清晰；
- 桌面端和移动端都能查看边界方法、可信度与来源；
- 无正式资格的几何不会被前端构建或发布包收录。
