# 项目路线图

本文件只记录当前范围、可验证任务和会影响后续工作的关键决策。实现细节留在代码，历史依据留在数据来源记录。

## 地图内容范围与推进顺序

- **基础必做**：行政建制、特殊治理、历史自然地理。
- **紧随行政骨架做**：军事防务中的都司、实土卫所、九边军镇。
- **先建数据模型，暂不全国采集**：总督、巡抚、分守道、分巡道和兵备道等督抚与守巡体系。
- **作为专题逐项开发**：漕运河道、盐政、驿传和王府。
- **暂不做辖区图层**：巡按御史、镇守太监、矿监税使等人物差遣，只保留未来事件与人物图层的扩展能力。

按察使司不单独绘制一套与布政使司高度重合的省级边界。需要独立表达的是其派出的分巡道、兵备道及具体监察活动，并且必须记录有效时间、辖区依据和制度性质。

左侧资料栏采用三种浏览入口，不平铺各类机构开关：

- **行政**：省级区域 → 府／直隶州 → 府属州 → 县。
- **军事**：军镇／都司 → 卫所 → 营堡关隘。
- **专题**：督抚与道、漕运河道、盐政、驿路等。

左栏主体负责当前体系的层级导航和实体资料；地图图层控制保持独立、精简。不同制度体系保留各自的隶属或管辖关系，不强制套用行政上下级结构。

## 全国州县落地计划

南京作为三级行政结构样本已经完成。其余区域按批次推进，每个区域独立录入、校勘、验证和交付，不等待全国数据一次性完成。

### 统一落地标准

每个区域必须同时满足以下条件，才能标记完成：

- 以公元 1600 年为切片，逐项核对府、直隶州、府属州及县名录；土府、土州、军民府、卫所等特殊体系不得强行改写为普通府州县。
- 保存真实父子关系；附郭县保持独立实体，共址只复用坐标事实，不合并行政单位。
- 每个州县治所具有名称、坐标、有效时间、定位方法、来源和可信度；无可靠同期点时明确标记代理坐标，不以现代位置冒充确定位置。
- 优先以正史地理志建立名录，以覆盖 1600 年的 CHGIS 点辅助定位，并使用地方志、历史地名辞典或专题研究复核疑难点；总目与逐项名录不一致时记录异文，不为凑数补造单位。
- 默认地图只显示府和直隶州；点击府后展开直属县、府属州与州属县，关系线遵循“直属县 → 府”“州属县 → 府属州 → 府”。
- 省级资料面板的行政数量将“州”统一计算为直隶州与府属州之和；“下辖单位”列表仍按直接父级关系显示，避免把层级汇总误作直属单位。
- 搜索、右侧资料面板、返回上级和同级切换均沿真实行政链工作，并至少选取一条“府 → 府属州 → 县”或等价特殊层级作为回归样本。
- 结构、时间、坐标、来源引用、前端构建、代码规范和 Rust 数据校验全部通过；该区域新增的低可信度及待考项进入工作备忘。

人口、户数和赋税资料继续使用独立统计记录，按史料可得性逐府州补充，不把统计资料齐全作为行政名录与定位落地的前置条件；当前省级覆盖统一以万历六年（1578）为人口、田产与赋税展示口径，县级行政单位继续保留，县级统计录入另行安排。每覆盖一个省，必须先完成府级与直隶州数据的查验罗列，再经确认后写入正式数据。

### 省级人口与赋税统计推进路线

每个省按“先查验罗列，后写入汇总”的独立批次推进。查验清单不直接视为正式数据，只有完成来源、原文、单位、统计性质和缺失项复核后，才进入对应数据分片并经 `data/manifest.json` 汇总。

#### 统一统计口径

- 人口：万历六年黄册体系下的户数、口数；特殊户籍原史料未分列时不另行估算扣除，并注明不等同于完整实际人口。
- 赋税：万历六年《大明会典》等可靠史料的原始分项，优先记录田产、本色夏税、本色秋粮；折色银无可靠统一记录时保留缺失，不以估算补齐。
- 层级：只录入府与直隶州统计，不把府级数值平均拆到县级；县级行政单位、搜索和关系链继续保留。
- 区域值：优先采用直接记载的省级总额；没有直接总额时，在府级与直隶州数据完整或缺失范围明确的前提下汇总，并标记为估算值。

#### 单省工作流程

1. 列出该省全部府与直隶州，确认万历六年的行政范围。
2. 逐单位查验户数、口数、田产、夏税、秋粮、折色银及原始来源；没有可靠记录的项目明确标记缺失。
3. 输出府级查验表，列出原文、数值、单位、记录年份、统计性质、来源、可信度和待核问题。
4. 完成查验确认后，才写入府级记录及省级直接总额或分项汇总记录。
5. 运行数据校验、构建、Lint，并核验省级面板、脚注、缺失提示和府级详情。

### 全国通用参考基线

全国州县名录以《明史》卷四十至卷四十六的地理志为共同起点，按各卷逐府、逐州读取，不只采用卷首汇总数字：

- 卷四十《地理一》：京师、南京。
- 卷四十一《地理二》：山东、山西。
- 卷四十二《地理三》：河南、陕西。
- 卷四十三《地理四》：四川、江西。
- 卷四十四《地理五》：湖广、浙江。
- 卷四十五《地理六》：福建、广东、广西。
- 卷四十六《地理七》：云南、贵州。

在线文本只作为检索和逐项摘录入口；遇到缺字、异文、总数不符、沿革时间跨越 1600 年或特殊治理体系时，应复核可靠点校本、影印本或地方志，不把协作录入文本本身视为最终校勘结论。

复旦 CHGIS Temporal Gazetteer 用于检索和辅助判断治所位置、同名异地及有效时间，不替代《明史》中的行政名录和隶属记载。采用 CHGIS 点时必须记录具体记录编号、有效区间、筛选理由、定位精度与许可信息；零坐标、同名误配、超出 1600 年有效期或只有多边形而无可发布点位的结果不得直接采用。

每个区域至少再配置一种独立复核来源，优先顺序为同期官方文献或地方志、可靠历史地名辞典、学术历史 GIS 与专题研究。无法获得第二来源的治所可以先以中低可信度进入工作数据，但必须进入待复核清单，不得提升为确定位置。

## 1600 年疆域表达扩展

“两京十三省”表示明代民政核心区，不直接等同于明朝全部政治空间。项目不制作一条将民政、军事实土、土司治理、羁縻册封和朝贡关系混为一体的单一国界，而按控制方式、时间有效性与证据强度分层表达。

### 表达层级

- **民政核心区**：两京十三省，使用府州县行政体系和经过许可审查的明确或重建边界。
- **实土军事治理区**：辽东都司及确有土地、人口、军户或屯田治理证据的实土卫所，作为与布政司并列但制度不同的疆土管理区域；无实土卫所不得据机构名称生成地域范围。
- **特殊治理区**：两京十三省内部的军民府、土府、土州、土司与兼理民政的卫所，保留原治理类型，不强制改写为普通府州县，也不重复计算为省外新增领土。
- **羁縻／册封关系区**：奴儿干都司相关女真卫所、乌思藏都司、朵甘都司及关西诸卫等，使用虚线、点网或半透明关系范围，并明确标注实际控制、存续时间与学术争议，不采用与民政核心区相同的实色边界。
- **朝贡与外交关系**：朝鲜、琉球、安南及蒙古诸部等不得因朝贡、互市或册封关系计入明代行政领土。

项目以免费公共版本积累用户、反馈和影响力，同时建设可持续支持研究与开发的收入渠道。CHGIS Temporal Gazetteer 点位当前采用 CC BY-NC 4.0，不能默认进入众筹回报、订阅服务或其他商业发布包。许可迁移采用两条并行路径：一方面申请 CHGIS 对免费展示、开发赞助、回报型众筹、订阅、导出和 API 的书面授权；另一方面从新增地点开始停止默认采用 CHGIS 点位，并按可审计的独立来源逐批替换现有点位。

数据按发布资格分为：

- **公共开放**：公共领域、明确开放许可或项目决定公开授权的原创内容，可进入免费公共版本。
- **商业安全**：允许商业使用的原创内容、兼容开放数据或具有单独书面授权的内容，可进入付费产品。
- **仅限非商业**：CHGIS 等带有 NC 限制的第三方内容，只能在许可允许的免费研究版本中使用。
- **授权不明**：权利范围尚未确认的内容，不得进入公开或商业发布包。

地点替换必须重新取得商业兼容的候选坐标，依据公版史料或许可明确的来源完成历史对应判断，并记录来源、定位方法、精度、可信度和校勘日期。不得通过移动、舍入、删改引用或重写说明把 CHGIS 点位标为原创；被替换记录的既有来源和修订关系保留在审计历史中，但不进入商业发布包。

## 已确认决策

### D1 · 时间基准

第一版采用公元 1600 年左右。朝代是浏览分类，年份与有效区间决定地图状态。

### D2 · 技术组合

浏览器使用 React、TypeScript 和 MapLibre；Rust 用于校验、转换和后续服务端，不以 Rust/WASM 重写地图 UI。

### D3 · 首版部署

优先使用静态 JSON/GeoJSON 和静态托管。没有动态需求前不引入后端和数据库。

### D4 · 代码与数据许可

项目不再预设代码采用 MIT，也不在权利分层完成前为全部原创数据预设统一许可。正式发布前分别决定代码、原创数据和商业服务的授权方式；在仓库未明确附加许可时，不视为已经向公众授予复制、修改或再分发权。第三方数据始终遵守原许可，免费公共版本与商业发布包分离，任何整体许可声明都不得覆盖或弱化第三方限制。具体迁移和商业发布门槛见“许可迁移与可持续开发”。

### D5 · 历史边界来源与发布

CHGIS V6 多边形不得默认再分发，也不得通过合并、简化或描摹规避许可。正式边界必须取得额外许可、采用兼容数据，或按可审计史料独立重建。公开历史地图上线前还需确认地图审核要求，详见 [历史边界重建规范](boundary-reconstruction.md)。

### D6 · 地形数据生成与部署

现代地形参考采用 CC0-1.0 的 NOAA ETOPO 2022 15角秒地表高程，以较低存储与传输成本生成全中国及邻近区域的多方向晕渲，输出分辨率约 480 米，缩放范围为 zoom 3–8。生成的源栅格、临时栅格和 PMTiles 不进入 Git；本地开发从被忽略的 `public/terrain/` 读取，上线后通过同一环境变量切换到支持 HTTP Range 的腾讯云 COS 地址。源数据版本、处理参数、生成日期与署名必须可审计。

### D7 · 历史统计记录

人口、户数和赋税采用独立的时间化统计记录，不作为行政单位的固定属性。当前人口、田产与赋税展示统一以万历六年（1578）为统计口径；史料原数与项目估算分离，府级数据不拆分至县。直隶区直接总额缺失时，可按完整的府州分项计算区域估算值并注明覆盖范围。每覆盖一个省，先逐府州查验并列出原文、数值、单位、来源、可信度和缺失项，经确认后再写入正式数据。县级行政链仍可展示，但县级统计不作为当前批次的录入范围。赋税保存原始分项与单位，只有依据充分时才提供带方法和可信度的统一换算值。

### D8 · 明代疆域分层表达

公元 1600 年地图以“两京十三省”为民政核心区，同时承认辽东等实土军事治理区域属于明代疆土管理体系。省内特殊治理单位保留制度差异；奴儿干、乌思藏、朵甘和关西诸卫等以羁縻、册封或边疆关系层单列，不与民政核心区使用同一边界语义。朝贡国和外交对象不计入行政领土，所有范围随时间有效性与证据强度变化。

### D9 · 地图内容优先级与左栏入口

当前范围以行政建制、特殊治理和历史自然地理为基础必做内容，军事防务紧随行政骨架推进。督抚、守巡道和兵备道先建立数据模型，暂不开展全国采集；漕运河道、盐政、驿传和王府在当前路线图任务完成后按专题逐项开发。人物差遣暂不制作辖区图层。

左栏使用行政、军事、专题三个浏览入口。机构类型不直接等同于地图边界，按察使司不重复绘制省界，不同体系按其真实空间语义分别使用辖区、路线、节点、驻地或关系表达。

### D10 · 资金支持与商业发布顺序

先以免费公共版本换取用户规模和研究反馈，以爱发电支持持续开发；完成首批商业安全数据后，再以摩点为范围明确的未来成果筹资；订阅服务只覆盖已经取得商业使用权的数据和功能。CHGIS 授权申请与独立替换同时推进，任何资金渠道都不能作为规避第三方许可条件的理由。

### D11 · 行政疆界交互与地貌叠加

山川地貌作为持续可见的基础层，行政疆界以半透明区域填色和分级边线叠加其上。交互参考大战略地图的区域悬停、点击选中、相邻区域切换和按缩放层级下钻方式，但保持历史不确定性说明与网页可访问性。行政面优先承担区域浏览，治所点和标签提供更精确的目标选择。

具体的图层顺序、缩放层级、可信度线型、点面点击优先级、详情联动和移动端行为，统一记录于[行政疆界显示与交互规范](administrative-boundary-display.md)。正式实现只制作省级和府级面，不因下钻自动生成县级边界。

疆界交互可以先用明确标记为内部用途的合成几何验证，但正式历史边界必须满足边界重建与商业发布资格要求。新增历史数据不再默认优先采用 CHGIS；授权申请、既有数据资格清单和商业兼容来源的独立重建并行推进。

当前不保留合成行政面。应天府试验推迟到都司卫所点位图层完成并验收后，具体准入与停止条件见[应天府行政边界绘制试验方案](yingtian-boundary-pilot.md)。

### D12 · 全国统计作用域

万历六年两京十三省直接总额独立保存于 `scopeStatistics`，全国总览面板读取该段记录；全国总额不挂接到京师、南京或任一单一行政单位。省级与府级记录继续使用 `statistics`，保持行政统计与全国总览作用域分离。

### D13 · 数据分片与跨体系关系

手工维护的数据按来源目录、单位体系和行政区域分片，`data/project.json` 只作为不入库的本地构建汇总产物。稳定地点与使用该地点的行政、军事或土司机构分开保存，避免共址点在不同类别中复制。

正式隶属、军事编制、总督巡抚管辖和战争期间的实际控制不强行压缩为一棵行政父子树。都司、卫所、宣慰司等具体关系按目标年份和来源逐项记录；关系与非行政区域几何在 `data/relations/` 和 `data/geometries/` 独立维护。当前迁移只建立目录、汇总和校验入口，不提前补录未经考证的关系。

### D14 · 主视图与归属色

行政、管辖和势力是独立的逻辑视图，不把它们压缩为同一张行政图层。地图每次只选择一个主视图作为点位归属色的来源，其他已接入的体系再作为可选的低透明度覆盖层叠加。行政模式按一级行政区域分色；巡抚、总督管辖和战争期间实际控制关系分别按各自关系记录分色；没有证据的归属使用中性色。

点位数据不保存固定颜色。机构类别使用标记形状和边框，可信度使用透明度、虚线和说明，选中状态使用光晕。当前前端启用行政模式，管辖和势力模式只保留接口，待关系数据按时间、来源和可信度完成后再开放。

### D15 · 都司军事图层与共址交互

第一批军事更新范围为都司、行都司和留守司。军事机构进入独立的军事图层，不并入府州县点位图层；“都司”开关统一控制都司、行都司、留守司和卫所，不为机构类型分别设置开关。行政圆点继续表示民政治所，军事机构统一使用正三角形；具体机构类型通过标签、详情和军事列表表达。

军事机构与行政区保持两类独立关系：军事指挥链按军事来源单独记录，所在省级地区或共址行政单位通过明确的跨体系关系连接，不以行政 `parentId` 替代军事隶属。地图显示上，都司、行都司、留守司和卫同属一级显示单位，卫通过关系线指向都司；千户所等“所”作为卫下二级单位，仅在选中卫时展开。军事点在行政着色视图中复用所在省级地区的配色 token；行都司和留守司使用同一省级基础色的军事变体；无法确定行政归属时使用中性色。军事着色只作用于军事点位，按五军都督府归属使用独立 token，不改变行政点位的行政着色。

行政和军事上下文采用“当前体系优先”的交互规则。行政上下文优先选择府州县圆点，军事上下文优先选择军事三角点；军事总览不因选中某一单位而隐藏同级卫，军事全域显示选中一级单位所属区域内全部一级、二级军事单位。共址单位仍保留在同一选择接口中，但选择后进入各自独立的详情和关系链。通用层级控制使用“总览／本级／全域”，行政、军事和后续特殊治理体系不得共用行政父链。

军事数据接入顺序按照[都司坐标独立定位方式与操作流程](dusi-coordinate-location-procedure.md)执行：先扩展军事单位类型、军事关系和跨体系关系的数据契约，再录入来源、有效时间、地点和可信度，随后完成组装、关系校验、军事图层、搜索、详情面板和共址回归样本。未经校勘的都司、行都司和留守司名录不得直接进入正式发布数据。
