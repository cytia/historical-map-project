# 项目路线图

本文件只记录当前范围、可验证任务和会影响后续工作的关键决策。实现细节留在代码，历史依据留在数据来源记录。

## 地图内容范围与推进顺序

- **基础必做**：行政建制、特殊治理、历史自然地理。
- **紧随行政骨架做**：军事防务中的都司、实土卫所、九边军镇。
- **先建数据模型，暂不全国采集**：总督、巡抚、分守道、分巡道和兵备道等督抚与守巡体系。
- **作为专题逐项开发**：漕运河道、盐政、驿传和王府。
- **暂不做辖区图层**：巡按御史、镇守太监、矿监税使等人物差遣，只保留未来事件与人物图层的扩展能力。

按察使司不单独绘制一套与布政使司高度重合的省级边界。需要独立表达的是其派出的分巡道、兵备道及具体监察活动，并且必须记录有效时间、辖区依据和制度性质。

左侧资料栏采用三种浏览入口，不平铺各类机构开关：

- **行政**：省级区域 → 府／直隶州 → 府属州 → 县。
- **军事**：军镇／都司 → 卫所 → 营堡关隘。
- **专题**：督抚与道、漕运河道、盐政、驿路等。

左栏主体负责当前体系的层级导航和实体资料；地图图层控制保持独立、精简。不同制度体系保留各自的隶属或管辖关系，不强制套用行政上下级结构。

## 全国州县落地计划

南京作为三级行政结构样本已经完成。其余区域按批次推进，每个区域独立录入、校勘、验证和交付，不等待全国数据一次性完成。

### 统一落地标准

每个区域必须同时满足以下条件，才能标记完成：

- 以公元 1600 年为切片，逐项核对府、直隶州、府属州及县名录；土府、土州、军民府、卫所等特殊体系不得强行改写为普通府州县。
- 保存真实父子关系；附郭县保持独立实体，共址只复用坐标事实，不合并行政单位。
- 每个州县治所具有名称、坐标、有效时间、定位方法、来源和可信度；无可靠同期点时明确标记代理坐标，不以现代位置冒充确定位置。
- 优先以正史地理志建立名录，以覆盖 1600 年的 CHGIS 点辅助定位，并使用地方志、历史地名辞典或专题研究复核疑难点；总目与逐项名录不一致时记录异文，不为凑数补造单位。
- 默认地图只显示府和直隶州；点击府后展开直属县、府属州与州属县，关系线遵循“直属县 → 府”“州属县 → 府属州 → 府”。
- 搜索、右侧资料面板、返回上级和同级切换均沿真实行政链工作，并至少选取一条“府 → 府属州 → 县”或等价特殊层级作为回归样本。
- 结构、时间、坐标、来源引用、前端构建、代码规范和 Rust 数据校验全部通过；该区域新增的低可信度及待考项进入工作备忘。

人口、户数和赋税资料继续使用独立统计记录，按史料可得性逐府县补充，不把统计资料齐全作为州县名录与定位落地的前置条件。

### 全国通用参考基线

全国州县名录以《明史》卷四十至卷四十六的地理志为共同起点，按各卷逐府、逐州读取，不只采用卷首汇总数字：

- 卷四十《地理一》：京师、南京。
- 卷四十一《地理二》：山东、山西。
- 卷四十二《地理三》：河南、陕西。
- 卷四十三《地理四》：四川、江西。
- 卷四十四《地理五》：湖广、浙江。
- 卷四十五《地理六》：福建、广东、广西。
- 卷四十六《地理七》：云南、贵州。

在线文本只作为检索和逐项摘录入口；遇到缺字、异文、总数不符、沿革时间跨越 1600 年或特殊治理体系时，应复核可靠点校本、影印本或地方志，不把协作录入文本本身视为最终校勘结论。

复旦 CHGIS Temporal Gazetteer 用于检索和辅助判断治所位置、同名异地及有效时间，不替代《明史》中的行政名录和隶属记载。采用 CHGIS 点时必须记录具体记录编号、有效区间、筛选理由、定位精度与许可信息；零坐标、同名误配、超出 1600 年有效期或只有多边形而无可发布点位的结果不得直接采用。

每个区域至少再配置一种独立复核来源，优先顺序为同期官方文献或地方志、可靠历史地名辞典、学术历史 GIS 与专题研究。无法获得第二来源的治所可以先以中低可信度进入工作数据，但必须进入待复核清单，不得提升为确定位置。

## 1600 年疆域表达扩展

“两京十三省”表示明代民政核心区，不直接等同于明朝全部政治空间。项目不制作一条将民政、军事实土、土司治理、羁縻册封和朝贡关系混为一体的单一国界，而按控制方式、时间有效性与证据强度分层表达。

### 表达层级

- **民政核心区**：两京十三省，使用府州县行政体系和经过许可审查的明确或重建边界。
- **实土军事治理区**：辽东都司及确有土地、人口、军户或屯田治理证据的实土卫所，作为与布政司并列但制度不同的疆土管理区域；无实土卫所不得据机构名称生成地域范围。
- **特殊治理区**：两京十三省内部的军民府、土府、土州、土司与兼理民政的卫所，保留原治理类型，不强制改写为普通府州县，也不重复计算为省外新增领土。
- **羁縻／册封关系区**：奴儿干都司相关女真卫所、乌思藏都司、朵甘都司及关西诸卫等，使用虚线、点网或半透明关系范围，并明确标注实际控制、存续时间与学术争议，不采用与民政核心区相同的实色边界。
- **朝贡与外交关系**：朝鲜、琉球、安南及蒙古诸部等不得因朝贡、互市或册封关系计入明代行政领土。

## 已确认决策

### D1 · 时间基准

第一版采用公元 1600 年左右。朝代是浏览分类，年份与有效区间决定地图状态。

### D2 · 技术组合

浏览器使用 React、TypeScript 和 MapLibre；Rust 用于校验、转换和后续服务端，不以 Rust/WASM 重写地图 UI。

### D3 · 首版部署

优先使用静态 JSON/GeoJSON 和静态托管。没有动态需求前不引入后端和数据库。

### D4 · 开源与数据许可

项目目前为公益开源，但第三方数据仍遵守原许可。代码拟采用 MIT，原创数据拟采用 CC BY 4.0；正式发布许可前复核全部数据兼容性。

### D5 · 历史边界来源与发布

CHGIS V6 多边形不得默认再分发，也不得通过合并、简化或描摹规避许可。正式边界必须取得额外许可、采用兼容数据，或按可审计史料独立重建。公开历史地图上线前还需确认地图审核要求，详见 [历史边界重建规范](boundary-reconstruction.md)。

### D6 · 地形数据生成与部署

现代地形参考采用 CC0-1.0 的 NOAA ETOPO 2022 15角秒地表高程，以较低存储与传输成本生成全中国及邻近区域的多方向晕渲，输出分辨率约 480 米，缩放范围为 zoom 3–8。生成的源栅格、临时栅格和 PMTiles 不进入 Git；本地开发从被忽略的 `public/terrain/` 读取，上线后通过同一环境变量切换到支持 HTTP Range 的腾讯云 COS 地址。源数据版本、处理参数、生成日期与署名必须可审计。

### D7 · 历史统计记录

人口、户数和赋税采用独立的时间化统计记录，不作为行政单位的固定属性。史料原数与项目估算分离，府级数据不拆分至县；赋税保存原始分项与单位，只有依据充分时才提供带方法和可信度的统一换算值。

### D8 · 明代疆域分层表达

公元 1600 年地图以“两京十三省”为民政核心区，同时承认辽东等实土军事治理区域属于明代疆土管理体系。省内特殊治理单位保留制度差异；奴儿干、乌思藏、朵甘和关西诸卫等以羁縻、册封或边疆关系层单列，不与民政核心区使用同一边界语义。朝贡国和外交对象不计入行政领土，所有范围随时间有效性与证据强度变化。

### D9 · 地图内容优先级与左栏入口

当前范围以行政建制、特殊治理和历史自然地理为基础必做内容，军事防务紧随行政骨架推进。督抚、守巡道和兵备道先建立数据模型，暂不开展全国采集；漕运河道、盐政、驿传和王府在当前路线图任务完成后按专题逐项开发。人物差遣暂不制作辖区图层。

左栏使用行政、军事、专题三个浏览入口。机构类型不直接等同于地图边界，按察使司不重复绘制省界，不同体系按其真实空间语义分别使用辖区、路线、节点、驻地或关系表达。
